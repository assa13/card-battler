# QTE-механики карт: среда, ревизия, правила дизайна

Документ для дизайна QTE-профилей карт (совместно с агентом-геймдизайнером —
его роль-промпт: `docs/card-qte-designer-prompt.md`).

## 1. Архитектура среды

Каждая боевая карта несёт декларативный **QTE-профиль**:

```javascript
qte: { mechanic: 'NONE' | 'PRECISION' | 'RHYTHM' | 'WINDUP', trigger: 'ALWAYS' | 'IMPORTANT' }
```

| Файл | Роль |
|---|---|
| `src/qteMechanics.js` | реестр механик `QTE_MECHANICS` + резолвер `resolveCardQte(card, ctx)` |
| `src/App.jsx` → `HERO_ABILITIES`, `MOD_CARDS` | сами карты с полем `qte` |
| `src/App.jsx` → `playCard` | раннеры механик (кольцо / стрим), точка помечена комментарием «НОВАЯ МЕХАНИКА» |
| `src/QteOverlay.jsx` | UI кольца точности (rAF, окна perfect/good/miss) |

Резолвер получает контекст розыгрыша `ctx = { chainPos, targets, expectedLethal }`
и возвращает id механики (или `null` — без QTE). Карта без поля `qte` получает
легаси-профиль (повторяет старые эвристики), но **все текущие карты размечены
явно** — легаси-ветка только страховка для будущих карт до их ревизии.

## 2. Инварианты движка (не обсуждаются с дизайнером)

1. **0 маны = никогда никакого QTE.** Спам-карты не должны душить игрока.
   Перекрывает любой профиль (`resolveCardQte` возвращает null до чтения профиля).
2. **Один QTE одновременно.** Пока кольцо/стрим активен, параллельные розыгрыши
   идут без QTE (`qteActiveRef`).
3. **QTE не задерживает пайплайн**, если не сыграл: мгновенный resolve(1.0).
4. Множители результата: perfect ×1.35, good ×1.15, miss ×1.0.
5. Скорость кольца: `calculateQteDuration` — базовое время минус штрафы за
   редкость и глубину комбо (сильнее карта → быстрее кольцо).

## 3. Текущие механики

| Механика | Что это | Когда уместна |
|---|---|---|
| `NONE` | без QTE | утилити/бафф-карты (`type: 'self'`), спам за 0 маны |
| `PRECISION` | одно сужающееся кольцо + bullet-time; при 2+ целях — большое в центре зоны врагов, при одной — над целью | одиночные и AoE-удары |
| `RHYTHM` | ритм-стрим: кольцо над каждой целью по очереди, пауза 100мс между звеньями; ближники «пинболом» рывками летят от цели к цели | мульти-удары (`targeting: 'random2'` и будущие цепные) |
| `WINDUP` | замах/подготовка удара: герой ждёт пика анимации, на оружии появляется короткий блик, игрок жмёт один раз в окно; ранний/поздний клик или игнор = miss ×1.0, удар всё равно проходит | тяжёлые физические удары, широкие свинги, точные добивающие разрезы |

Триггеры:

- `ALWAYS` — механика является **идентичностью карты**, играет каждый розыгрыш.
- `IMPORTANT` — только в значимый момент: звено комбо 2+, редкость EPIC/LEGENDARY,
  среди целей босс или цель с Меткой, либо удар ожидаемо летален.

Особый случай: `RHYTHM` при одной живой цели деградирует в кольцо `PRECISION`
по правилу `IMPORTANT` (стрим по одной цели не отличим от обычного удара).

Логика распределения: **все random2 = RHYTHM/ALWAYS** (стрим — витрина
мульти-удара); **тяжёлые замахи и добивающие разрезы = WINDUP** (блик на
оружии/лезвии вместо абстрактного кольца, miss всё равно наносит базовый урон);
**сигнатурные магические нюки EPIC+ = PRECISION/ALWAYS** (дорогая карта — всегда
момент внимания); **рядовые удары и AoE = PRECISION/IMPORTANT** (кольцо
подчёркивает значимые моменты, не превращаясь в рутину); **утилити = NONE**.

## 5. Как добавить новую механику (чек-лист для агента)

1. **Реестр**: запись в `QTE_MECHANICS` (`src/qteMechanics.js`) — id, name,
   комментарий с описанием. Приоритетная новая механика: `WINDUP` (дождаться
   блика на оружии и нажать один раз в окно); остальные заготовки: `MASH`
   (N кликов за время).
2. **Резолвер**: если механике нужны особые условия применимости (по числу
   целей, типу урона и т.п.) — ветка в `resolveCardQte` по образцу `RHYTHM`.
3. **UI**: новый оверлей-компонент (по образцу `QteOverlay.jsx`: rAF-анимация,
   full-screen клик-катчер, resolve(multiplier), поддержка bullet-time
   `qteSlowMo`).
4. **Раннер**: ветка в `playCard` (`App.jsx`) по значению `qteMechanic` —
   точка подключения помечена комментарием «НОВАЯ МЕХАНИКА». Обязательно:
   захват `qteActiveRef` на время механики и освобождение в resolve.
5. **Разметка карт**: обновить профили `qte` затронутых карт + таблицы в
   этом документе (раздел 4).
6. **Проверка**: `npx eslint src` и `npm run build` — чисто.

## 6. Дизайн-принципы QTE (для оценки предложений)

- QTE — **награда за внимание**, не налог: миссы не наказывают ниже ×1.0.
- Частота: у игрока в среднем 1–2 кольца за ход, не больше — иначе усталость.
  Поэтому дефолт для рядовых карт `IMPORTANT`, а `ALWAYS` — только идентичность.
- Каждая механика должна читаться мгновенно (без обучалки) и разрешаться
  за < 1.5 секунды реального времени.
- Механика обязана поддерживать bullet-time и прерываемость (resetGame,
  смерть цели до резолва).
