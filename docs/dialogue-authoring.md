# Инструкция: адаптация историй в диалог-скрипты (система Yarn-like)

Этот документ — для агента, которому пользователь даёт **историю в свободной
форме** (текст, набросок сцены, идею персонажа). Твоя задача — превратить её в
**диалог-скрипт** нашего формата и зарегистрировать его в игре. Ничего в коде
раннера менять не нужно.

## 1. Как устроена система (в двух словах)

Модель заимствована у Yarn Spinner / Ink: история — это **граф узлов**.

- **Узел (node)** = реплики одного спикера + опционально выборы игрока и команды.
- **Реплики (lines)** печатаются тайпрайтером в пиксель-арт пузыре над спикером;
  клик ускоряет печать, следующий клик — следующая реплика.
- **Выборы (choices)** появляются после последней реплики узла — панель кнопок
  внизу экрана. Выбор может выполнить команды и прыгает в следующий узел.
- **Команды (commands)** — триггеры-последствия: награды, флаги, завершение
  ночи, тосты. Выполняются при входе в узел или при клике по выбору.
- **Состояние прогона** (flags/vars) живёт только внутри одного диалога —
  им управляют внутренние команды, а условия (condition) прячут/показывают выборы.

Файлы системы:

| Файл | Роль |
|---|---|
| `src/dialogue/scriptRunner.js` | формат, условия, команды — ядро (не трогать) |
| `src/dialogue/DialogueScriptOverlay.jsx` | UI-раннер (геометрия/стили — зона верстальщика, см. `layout-designer-prompt.md`) |
| `src/dialogue/NightEncounterScreen.jsx` | полноэкранная сцена ночной встречи (геометрия — зона верстальщика) |
| `src/dialogue/scripts/*.js` | **сюда кладёшь новые скрипты** |
| `src/dialogue/scripts/nightWanderer.js` | эталонный пример + реестр ночных гостей |

Ночной поток: игрок кликает по двери в фазе стука → открывается
`NightEncounterScreen` (полноэкранная сцена с гостем) → на нём играет скрипт,
выбранный взвешенным роллом из реестра.

## 2. Формат скрипта

```javascript
export const MY_SCRIPT = {
  id: 'night_my_story',            // уникальный snake_case id
  speakers: {                       // словарь спикеров этой истории
    stranger: { anchorEntityId: 'door_night', name: 'Голос за дверью' },
    barkeep:  { anchorEntityId: 'npc_bartender', name: 'Бармен' },
  },
  start: 'intro',                   // id стартового узла
  nodes: {
    intro: {
      speaker: 'stranger',          // ключ из speakers
      lines: ['Реплика 1.', 'Реплика 2.'],
      commands: [ /* при входе в узел */ ],
      choices: [                    // ЛИБО choices, ЛИБО next
        {
          text: 'Открыть дверь',    // подпись кнопки
          next: 'let_in',           // куда прыгаем
          condition: { notFlag: 'scared' },   // опционально: когда виден
          commands: [{ type: 'SET_FLAG', flag: 'opened' }], // опционально
        },
      ],
      next: 'other_node',           // если choices нет; null/нет поля = конец
    },
  },
};
```

Правила:

- Узел без `lines` и без `choices` — **логический**: мгновенно выполняет
  `commands` и проскакивает в `next`. Используй для «узлов-наград» и развилок.
- Узел-хаб с выборами можно посещать повторно (петля «спросить совета» → назад);
  команды узла выполняются **на каждый визит** — не клади туда награды.
- Конец диалога — узел с `next: null` (или без `next`) и без выборов.
  **Каждая концовка ночной истории обязана заканчиваться `END_NIGHT_SLEEP`**,
  иначе игрок застрянет в ночи.

## 3. Спикеры и их якоря (anchorEntityId)

Пузырь вешается над DOM-узлом с `data-entity-id === anchorEntityId`.

**Ночные истории играют на экране встречи (`NightEncounterScreen`)** — там
доступен ровно один якорь:

| anchorEntityId | Кто это |
|---|---|
| `encounter_visitor` | ночной гость на экране встречи |

Спикеры без валидного якоря (рассказчик, голос со стороны) не ломают диалог —
пузырь встаёт в центр верхней трети экрана.

Экран встречи рисует по центру смотровое окошко в двери
(`./assets/encounters/door_window.webp`), масштабируемое как сцена Таверны.
Гость виден ЗА окном (отдельный слой, дыра в самом арте, без маски-клиппинга).

### Персонаж истории (`encounter`)

Персонаж выбирается **по id из реестра** `src/dialogue/encounterCharacters.js`
(`ENCOUNTER_CHARACTERS`), позиция — **смещение от центра** холста 3200×1800:

```javascript
encounter: {
  character: 'cloaked_visitor', // id из ENCOUNTER_CHARACTERS
  offset: { x: 160, y: -40 },   // px от центра холста (опц.; + вправо/вниз)
  size: 1813,                   // высота спрайта в px холста (опц.)
  flipX: true,                  // горизонтальный флип (опц.)
},
```

Доступные персонажи (реестр может расширяться — сверься с файлом):

| id | Кто это |
|---|---|
| `eye` | монстр «Глаз» (дефолт) |
| `bandit`, `wolf`, `goblin`, `zombie`, `orc`, `dark_mage`, `squish`, `shooter` | боевые монстры |
| `cloaked_visitor`, `common_visitor`, `barman` | люди из таверны |
| `stranger` | наёмник Незнакомец (атлас 4×4, курит трубку) |

Все поля опциональны: без `encounter` гость — дефолтный монстр в постановке
Figma (offset `{x:160, y:-40}`, size 1813, flipX). Нового персонажа НЕ вписывай
в скрипт напрямую — добавь запись в реестр `ENCOUNTER_CHARACTERS` (ассет уже
должен лежать в `public/`). Легаси-поля `visitorAtlas` / `visitorUrl` ещё
работают, но в новых историях используй `character`.

**Выделение слов в реплике:** обернуть фрагмент в `**двойные звёздочки**` —
раннер (`variant="plate"`, экран ночной встречи) покрасит его в золотистый
акцент (`#FFCD76`), тайпрайтер печатает разметку прозрачно (без сбоя тайминга).
Пример: `'Братан..прикинь, **ушел с пивом**, надо вернуть кружку'`.

Для дневных диалогов на сцене таверны (система линейных баек
`DialogueConfig.js`) якоря — id сущностей из `TavernSceneConfig.js`
(`npc_bartender`, `hero_slot_0..2`, `visitor_*`).

## 4. Словарь команд

Внутренние (состояние прогона, исполняет раннер):

| Команда | Поля | Смысл |
|---|---|---|
| `SET_FLAG` | `flag`, `value?` | поставить флаг (по умолчанию true) |
| `CLEAR_FLAG` | `flag` | снять флаг |
| `SET_VAR` / `ADD_VAR` | `var`, `value` / `amount` | числовые переменные |

Условия выборов: `{ flag: 'x' }`, `{ notFlag: 'x' }`, `{ var: 'trust', gte: 2 }`
(также `lte`, `eq`).

Внешние (исполняет `TavernHubScreen.handleScriptCommand`):

| Команда | Поля | Эффект |
|---|---|---|
| `END_NIGHT_SLEEP` | — | свернуть ночь: вуаль, отдых засчитан, рассвет |
| `SHOW_TOAST` | `text` | всплывающее сообщение на 2 секунды |
| `UNLOCK_HERO_CARD` | `heroId`, `cardId` | разблокировать карту конкретному герою (p1/p2/p3) |
| `GIVE_GOLD` | `amount` | +огоньки души (`soulEmbers`) |
| `STRANGER_JOIN_TAVERN` | — | Незнакомец перманентно поселяется в таверне (сюжет 2-й смерти) |

Прочие команды (`SPAWN_TAVERN_VISITOR`, …) пробрасываются в `App.jsx` через
`onAction({ action: 'DIALOGUE_COMMAND', command })`. **Проверь, что App их
обрабатывает**; если нет — реализуй обработку в onAction-диспетчере Таверны в
`App.jsx` или согласуй с пользователем заглушку (`SHOW_TOAST` как временный
эффект — допустимо).

## 5. Хранение и регистрация историй

**Одна история = один файл** `src/dialogue/scripts/<имя>.js` (camelCase).
Все истории в монолит не сваливаются — реестр только импортирует их.

Реестр — `src/dialogue/scripts/index.js`: ночной гость выбирается взвешенным
роллом из `NIGHT_VISITOR_SCRIPTS` при клике по двери ночью:

```javascript
// src/dialogue/scripts/index.js
import { NIGHT_WANDERER_SCRIPT } from './nightWanderer';
import { MY_NEW_SCRIPT } from './myNewStory';   // ← импорт нового файла

export const NIGHT_VISITOR_SCRIPTS = [
  { script: NIGHT_WANDERER_SCRIPT, weight: 1 },
  { script: MY_NEW_SCRIPT, weight: 0.5 },        // ← одна запись на историю
];
```

Чек-лист новой истории:
1. Файл `src/dialogue/scripts/<имя>.js` с `export const <ИМЯ>_SCRIPT = {...}`.
2. В скрипте: `id`, `encounter` (персонаж + позиция), `speakers`, `start`, `nodes`.
3. Импорт + запись с weight в `src/dialogue/scripts/index.js`.
4. `npx eslint src/dialogue` и `npm run build`.

**Сюжетные (не ночные) скрипты.** История может запускаться не роллом двери,
а игровым событием (пример — `strangerSecondDeath.js`: визит Незнакомца после
2-й смерти). Такой скрипт в `NIGHT_VISITOR_SCRIPTS` **не регистрируется** —
только реэкспортируется из `index.js`, а `App.jsx` передаёт его в таверну
пропом `entryScript` (играет на экране встречи при входе, вместо линейной
болтовни). Концовки завершаются `next: null` БЕЗ `END_NIGHT_SLEEP` — сюжетное
событие не даёт бесплатный отдых.

## 6. Правила адаптации текста (важно для UI)

1. **Реплики короткие**: пузырь имеет max-width 200px — держи реплику в
   пределах ~70–90 символов, длинную мысль дроби на несколько `lines`.
2. **Тон** — мрачное тёмное фэнтези, как существующие истории в
   `src/DialogueConfig.js`. Без смайлов и современного сленга.
3. **Подписи выборов** — 1–4 слова, глагольные («Открыть дверь», «Прогнать»).
4. **Выборов в узле 2–4**, не больше (панель не скроллится).
5. Язык — русский.

## 7. Чек-лист перед сдачей

- [ ] Все `next`/`choices[].next` указывают на существующие узлы (или `null`).
- [ ] Каждый путь достигает концовки с `END_NIGHT_SLEEP` (для ночных историй).
- [ ] Награды лежат в **логических узлах-концовках**, не в узлах-хабах.
- [ ] Спикеры используют только доступные ночью якоря.
- [ ] Скрипт зарегистрирован в `NIGHT_VISITOR_SCRIPTS` с весом.
- [ ] `npx eslint src/dialogue` и `npm run build` — чисто.

## 8. Мини-пример адаптации

История пользователя: «Ночью стучит торговец, предлагает купить амулет за 30
золота, бармен говорит что он мошенник, если купить — амулет исчезает утром».

Схема: `intro` (торговец предлагает) → `hub` (выборы: Купить / Спросить бармена
[однократно, флаг] / Отказаться) → `buy` (ADD команды: забрать золото, тост,
флаг `bought`) → `end`; `barkeep_warn` → назад в `hub`; `refuse` → `end`.
Каждая концовка — `END_NIGHT_SLEEP`. Полный образец кода — в
`src/dialogue/scripts/nightWanderer.js`.
