# Подземелье вместо карты сектора

Тестовая ветка: `test/dungeon-sector-map`. Локальный запуск: `http://127.0.0.1:5185/`.
Рабочая копия: `C:/Users/sirpu/idler_godot/gemini-code-1778448634953-dungeon-test`.

## Принятые решения

- Один уровень размером 18 × 6 тайлов соответствует одному сектору.
- Подземелье заменяет старую схему узлов в основном игровом маршруте,
  включая обе версии боевого интерфейса. Таверна и остальная игра сохранены.
- Герой ходит стрелками, WASD или кликом по полу. Соседние враги и сундуки
  подсвечиваются жёлтым. Взаимодействие доступно с соседней по стороне клетки.
- Клик на лестницу выхода прокладывает путь к ней. Достижение клетки перед
  выходом открывает переход в следующий сектор. Зачистка не требуется.
  Повторный ввод во время перехода блокируется.
- Победа над любым противником, включая босса, возвращает на ту же карту.
  Удаляется только побеждённая встреча, положение героя сохраняется.
- Сундуки не запускают бой: сразу открывается прежний выбор усиления.
  После выбора сундук исчезает. Вариант с картами открывает обычный выбор карт.
- Вход позволяет вернуться в таверну без штрафа; уход через кнопку похода
  вдали от входа использует прежние правила потери предметов.

## Состав противников

| Миниатюра | Обязательный участник боя |
| --- | --- |
| `wolf` | Волк |
| `zombie` | Зомби |
| `dark_wized` | Тёмный маг |
| `boss_skeletal_golem` | Костяной Король |

Обычный бой содержит от одного до трёх врагов в зависимости от сложности.
Миниатюра гарантирует как минимум одного соответствующего противника.
Остальные участники выбираются из прежнего пула врагов сектора.
Даже если обязательного вида нет в этом пуле, он сохраняется в составе.
Миниатюра костяного босса запускает бой с этим боссом, а не с прежним боссом
по номеру сектора. Здоровье, опыт и сила используют существующее масштабирование.
Этап сложности (1–5) определяется расстоянием встречи от входа по полу.

## Состояние забега

Бой запускается внутри существующего `App`, без создания отдельного отряда.
HP, колода, уровень, экипировка и инвентарь продолжают принадлежать общему
состоянию игры. Награды и прогресс поручений проходят прежний путь.
При переходе сектора действует прежнее восстановление отряда и перемешивание
колоды; смерть и добровольный выход используют прежний сброс забега.

Карта и её зачищенные встречи живут до смены сектора, сброса забега или
перезагрузки страницы. Сохранение карты между перезагрузками не добавлено.
Изолированный маршрут `#dungeon` остаётся витриной прототипа: у него своя
тестовая боевая сессия и прежнее поведение сундуков. Проверять внедрение нужно
в основной игре, перейдя из таверны в поход.

## Код и запуск

- `src/dungeon/SectorDungeon.jsx` — карта внутри существующей панели игры;
  использует атлас, рендерер, свет и движение прототипа.
- `src/dungeon/sectorDungeonState.js` — переход через выход, описание встречи,
  гарантированный состав врагов. Геометрия берётся из `dungeonGenerator.js`.
- `src/App.jsx` — владелец карты и отряда, запуск боя/события, возврат,
  существующий переход сектора. Старый граф узлов удалён.
- `vite.config.js` — отдельный кэш Vite, чтобы тестовый запуск не затрагивал
  кэш сервера основной рабочей копии.

```sh
npm run dev -- --host 127.0.0.1 --port 5185 --strictPort
node --test src/dungeon/sectorDungeon.test.js src/dev/dungeonInteraction.test.js src/dev/dungeonGenerator.test.js
```

13 проверок проходят: 5 000 вариантов генерации, движение, встречи,
соответствие миниатюр составу, сундуки-события и выход без зачистки.
Линтер новых модулей проходит. В `App.jsx` сохраняются прежние замечания
линтера; их количество снизилось после удаления старой карты.
Сборка и прохождение боёв не выполнялись.
