# Правило: три размера атласов иконок

Все emoji и небольшие символьные изображения, собранные для интерфейса игры,
хранятся в **трёх отдельных атласах**. Объединять их обратно в общий лист нельзя.

| Класс (`sizeClass`) | Ячейка | Что сюда относится |
| --- | --- | --- |
| `small` | 32 × 32 px | Служебные значки: замок, стрелки, галочки, закрытие, плюс/минус, звук, ожидание, разделители |
| `medium` | 64 × 64 px | Валюты, ресурсы, здоровье, награды, статусы и эффекты состояния |
| `large` | 128 × 128 px | Иллюстративные значки: оружие, способности, магия, персонажи и объекты |

## Как выбирать группу

1. Выбирать по основной роли иконки в интерфейсе, а не по размеру исходного PNG.
2. Для собранных emoji исходное распределение определяется категорией:
   «Управление» и «Оформление» → `small`; «Валюты и ресурсы» и «Статусы» →
   `medium`; «Оружие и магия» и «Персонажи и объекты» → `large`.
3. Один и тот же рисунок, используемый в нескольких местах, хранить один раз.
   Если необходимы самостоятельные варианты с разной детализацией, создавать
   отдельные ID и PNG, явно указывая размер каждого варианта.
4. Неизвестные новые значки по умолчанию попадают в `medium`. Перед перерисовкой
   проверить назначение и при необходимости изменить `sizeClass` в каталоге.
5. Категория помогает первичному распределению. После добавления источником
   истины является явное поле `sizeClass`; пересборка не меняет его автоматически.

## Сетка и редактирование

- Все ячейки квадратные; прозрачный фон; восемь столбцов в каждом листе.
- Новые иконки добавлять в конец своего атласа. Существующие слоты не сортировать,
  не уплотнять, не переиспользовать автоматически; свободные ячейки сохранять.
- Идентификаторы `id` и глобальные номера `slot` сохранять.
  Координаты определяются парой `sizeClass` + `atlasSlot`, а не `slot`.
- При переносе в другую группу менять `sizeClass` и сбрасывать `atlasSlot` в `null`.
  Пересборка назначит новый слот, не сдвигая соседей.
- Размер ячейки — разрешение экспортируемого рисунка, а не обязательный CSS-размер.
  Разделение атласов само по себе не меняет интерфейс игры.
- Редактируемые исходники лежат в `icons/` по 128 × 128 px. Для маленьких и
  средних значков детали следует проектировать под итоговые 32 / 64 px.
  Масштабирование выполняется nearest-neighbor, без сглаживания.
- Перерисовывать можно отдельный PNG или весь прозрачный атлас. При работе
  целым листом сохранять размер, порядок, прозрачность и границы ячеек.
  Обзорный лист с подписями не является исходником для импорта.
- После изменений запускать `python scripts/build-emoji-atlas.py`.
  Координаты в `manifest.json` генерируются; вручную их не править.

Команды импорта и добавления описаны в [README.md](README.md).

## Подключение маленьких иконок в игре

- Использовать `SmallIcon` из `src/ui/SmallIconText.jsx` для явного значка
  (`<SmallIcon name="lock" />`) или `SmallIconText` для текстовой подписи
  с известными символами (`<SmallIconText>{label}</SmallIconText>`).
- Размер по умолчанию — `2em`: все маленькие иконки увеличены вдвое
  относительно первоначального подключения и масштабируются вместе с интерфейсом.
  При необходимости передавать `size` в `SmallIcon`. Используется pixelated.
- Заменять символы на этапе отображения. Значения игровых данных, вычисления,
  `title`, `aria-label`, строки диалогов и нативные элементы ввода оставлять текстом.
- `+` везде отображается обычным шрифтовым символом с размером окружающего
  текста, без увеличения ×2 и без атласа, включая вызов `SmallIcon name="plus"`.
  Изображение в исходном атласе сохраняется только как заготовка.
- `!`, `?`, `-` распознаются как иконки только отдельным символом:
  знаки препинания внутри предложений и дефисы в словах не заменяются.
- Не копировать координаты вручную: `scripts/sync-small-icons.mjs` публикует
  PNG и компактный JSON из общего манифеста. Скрипт вызывается при пересборке.
  Ревизия в URL меняется вместе с изображением, чтобы браузер обновлял рисунок.
